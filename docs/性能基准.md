## 1. 结论摘要

| 指标 | 目标 | 实测 | 判定 |
| --- | --- | --- | --- |
| 画布交互帧率 | 30 组件 / 50 连线 **≥ 50 FPS** | 27 节点 / 58 连线：**帧间隔中位 5.6 ms（≈178 FPS）**，拖动中同样 5.6 ms，最差帧 38.9 ms，长任务 0 | ✅ 达标（余量 3.5 倍以上） |
| `POST /validate` P95 | 100 组件 / 150 连线 **< 300 ms** | 200 次实测：p50 **15.4 ms**、p95 **16.6 ms**、max 19 ms | ✅ 达标（余量 18 倍） |
| 首屏可交互 | 生产构建 + 4G 节流 **< 2 s** | **542 ms**（TTFB 2 ms、DCL 399 ms） | ✅ 达标（余量 3.7 倍） |
| 端到端校验（点击运行 → 结果呈现） | —（参考项） | 中位 **63 ms**、最差 77 ms（5 次） | ✅ 体验顺滑 |
| 本地规则引擎耗时（30 组件） | < 16 ms（一帧内） | 中位 **1 ms** | ✅ 达标 |
| 冒烟执行时长 | < 60 s | 约 40 s（37 项断言） | ✅ 达标 |

**结论：NFR-01 / NFR-02 全部达标，无需启用技术文档 §12.2 的任何优化项。**

## 3. 测量方法

| 项 | 方法 |
| --- | --- |
| 帧率 | 页面内 `requestAnimationFrame` 采样帧间隔（丢弃首尾若干帧），同时用 `PerformanceObserver({ entryTypes: ['longtask'] })` 统计 >50 ms 长任务；拖动负载为"按住一个节点 + `steps` 插值移动" |
| 端到端校验 | 连续 5 次点击「运行」，计时至结果状态呈现（`.result-status` 出现且 `.result-running` 消失） |
| 后端 P95 | Node 侧直打 `POST /api/v1/validate`（100 组件 / 150 连线负载）**200 次**，取 p50/p95/max；已预热 1 次 |
| 首屏 | CDP `Network.emulateNetworkConditions` 节流后 `goto` → 等 `.board-node` 出现（= 画布可交互） |
| 本地引擎 | 由端到端链路间接覆盖（引擎为纯函数，单测中有正反例与可复现性保障） |

复现命令：

```bash

cd apps/web && npx vite preview --port 4174
node scripts/bench.mjs --web http://127.0.0.1:4174 --fps-seconds 6
```

## 4. 方法学备注（三个坑，值得记住）

### 4.1 绝对不要在 dev server 上测性能

同一套代码、同一台机器，**dev server 下测出的拖动帧率是 12.8 FPS / 9 FPS —— 完全是假象**：

| 环境 | 拖动时帧间隔中位 | 主线程 `script` 耗时（5 s 内） |
| --- | --- | --- |
| dev server（vite dev） | 77.9 ms（≈12.8 FPS） | **4283 ms** |
| 生产构建（vite build + preview） | **5.6 ms（≈178 FPS）** | 可忽略（长任务 0） |

V8 CPU 剖析显示 dev 环境下大量时间花在 React 开发模式的 `jsxDEV`、`validateProperty`、`warnUnknownProperties`、`warnInvalidARIAProps` 上 —— 这些在生产构建中不存在。

> **规矩**：性能基准一律以生产构建为准；dev 数据只能用于"是否存在量级问题"的粗判。

### 4.2 不要用逐次 `page.mouse.move` 测"单帧成本"

首次实现用 playwright 逐次移动鼠标（每次 `waitForTimeout(120ms)`）拖动，得到"移动 42 次 → 42 个长任务"的结论，看似"每次交互 >50 ms"。实际上 CDP 事件派发的往返开销被计入了页面主线程 —— 是**测量方式的假象**。改用「一次移动 + `steps` 插值多步」后，长任务归零。

### 4.3 headless 的 rAF 不受 vsync 限制

静态场景会跑出 178 FPS 这类"超高帧率"，不能直接当作"性能有多好"的证据。因此判读口径定为 **帧间隔中位数 ≤ 20 ms ⇔ ≥50 FPS**。

## 5. 优化记录

基准过程中顺手做了两项低风险优化（CanvasArea / 节点组件）：

1. `ComponentNode` / `BoardNode` 用 `React.memo` 包裹；
2. 节点 `data` 引用稳定化（内容不变则复用对象），让 memo 真正生效。

**诚实说明**：这两项优化在本轮的对照测量中**未观测到显著差异** —— 因为此前的"卡顿"主要来自开发模式开销（见 4.1）。保留它们是因为：

- 它们让"拖动时全体节点重渲染"这一潜在问题在**大项目（60+ 组件）**下不会变成瓶颈；
- 成本极低（无行为变化），并有完整回归（43 例单测 + 37 项冒烟全绿）。
